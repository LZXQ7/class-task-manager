# 审核通过后 · 关闭「审核体验入口」操作单

> 适用版本：**v1.0.6.3**（内部 v0.7.37）· 建于 2026-10-11
> 一句话：**审核通过当天，跑两条 SQL 就行，不用重新发前端。**

---

## 一、为什么要关

这个入口本质是「**知道口令就能当超管**」的后门。口令写在 mp 后台「审核备注」里，审核员与知情人手里都有；
不关 = 线上长期挂着一个公开的超级管理员通道。

## 二、最省事的做法（推荐）

在项目根目录执行（我之前都是这么跑的）：

```bash
bash scripts/run_sql_file.sh scripts/disable-review-demo.sql
```

看到 `=== 成功 4 失败 0 ===` 即完成（2 条 UPDATE + 2 条验证查询）。

**或者**让我来跑——你只要说一句「审核通过了，关掉」即可。

## 三、手动执行版（不想用脚本时）

在 CloudBase 控制台的数据库里依次执行：

```sql
-- ① 关开关 + 清口令（两个条件都置，缺一不可）
UPDATE `class` SET review_demo_on = 0, review_demo_code = '' WHERE id = 3;

-- ② 清掉体验者绑定（别漏这一步！）
UPDATE member SET openid = NULL WHERE id = 69;
```

## 四、怎么确认真的关掉了

跑下面两条查询，结果符合就说明成了：

```sql
SELECT id, review_demo_on, review_demo_code FROM `class` WHERE id = 3;
-- 期望：review_demo_on = 0，review_demo_code = 空

SELECT id, student_no, (openid IS NULL) AS unbound FROM member WHERE id = 69;
-- 期望：unbound = 1（体验超管的 openid 已清空）
```

**表层表现**：下次冷启动小程序，首页**不再出现**「审核体验入口」区块（即使手动输入口令也会提示「体验入口未开放」）。

---

## 五、四个容易踩的坑

| 坑 | 说明 |
|---|---|
| **以为要重新发前端** | ❌ 不用。入口是**运行时**判断的（`wx:if="{{reviewOn}}"` ← `login` 下发的 `config.reviewDemo` ← 读库）。跑完 SQL 线上立即生效。 |
| **只关开关、不清 `openid`** | ⚠️ 最常见。已经进去过的那个微信会**一直持有测试超管身份**，直到他自己解绑。必须跑第 ② 条。 |
| **忘了在 `class.id = 3` 这一行上操作** | ⚠️ 开关是**按班级行**存的。当前 5 个班里只有 **id=3（示例专业A1班）** 被开启；改错行等于没关。 |
| **以为关掉后审核员看到的还是旧页面** | ⚠️ 已打开的小程序实例里 `config` 是 onLaunch 时拉的，**需要彻底退出重进**（或杀进程）才会拿到新的 `reviewDemo=false`。对审核无影响，只是你自己复测时要注意。 |

## 六、如果审核被驳回、需要再次提审

重新开启（**建议同时换一个新口令**，旧口令已在审核备注里暴露过）：

```sql
UPDATE `class` SET review_demo_on = 1, review_demo_code = '<新口令>' WHERE id = 3;
```

改完把新口令同步到 mp 后台「审核备注」即可。前端无需任何改动、无需重新上传。

> 换口令的取法（高熵、去掉易混字符 I/O/0/1）：
> ```bash
> node -e "const c=require('crypto');const A='ABCDEFGHJKLMNPQRSTUVWXYZ23456789';let s='';const b=c.randomBytes(16);for(let i=0;i<14;i++){s+=A[b[i]%A.length];}console.log('LXQ-'+s.slice(0,4)+'-'+s.slice(4,8)+'-'+s.slice(8,12)+'-'+s.slice(12,14));"
> ```
