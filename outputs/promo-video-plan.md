## 1. 仓库能力核实（不是道听途说）

它是一套**给 Agent 用的制作技能包**，不含「一键成片」的模型，靠 Remotion 代码合成：

- **152 张镜头配方卡 + 209 个样式**：每张卡给用途、能量、建议时长、参数表、**已知坑**，并附一份调校过的 demo TSX（缓动/时值比/摘罩时机都在里面）。
- **1 支已验收完整模板 Ink Press**：36.2s / 1920×1080 / 30fps / 10 镜 / SFX-only。
- **可复用组件**：`PageCam`（2.5D 页面相机，一切「真实页面」镜头的地基）、`DigitRoll`、`FlashCut`、`Caption`、`FlatPanel`、`VerticalTicker`。
- **音频资产**：5 首 BGM + 149 个 SFX（16 类场景，Mixkit 免费商用）。
- **8 阶段流水线**：产品理解 → 视觉方向 → 功能到镜头映射 → 分镜 → 采素材 → 逐镜实现 → 声音设计 → 独立终检。
- **附加**：可导出剪映工程（字幕/变速/音频仍可改）；本地 Gallery 可在浏览器里翻卡挑镜头。

它**明确不做**的事：不产出 AI 生成视频、不代替拍摄、不做网页设计——它只负责「把已有产品的真实界面，用电影语言重排成一支片」。

## 2. 它需要什么：素材 / 输入参数 / 配置项

### 2.1 素材三件套（每页一套，硬要求）

按 `assets/scripts/capture-template.mjs` 的产出物：

| 件 | 规格 | 用途 |
|---|---|---|
| 全页 2x 截图 | viewport 1920×1080、`deviceScaleFactor: 2`，截前等 `fonts.ready` + 600ms | 作为 2.5D 相机的「底图」，所有推拉摇移都在它上面做 |
| 元素级切片 | 按语义选择器逐元素截，悬浮件用**透明底**，另备**空 backplate** | 「卡片飞入空板」「元素逐条嵌入」这类镜头 |
| `layout.json` | 每元素整页坐标 `{x,y,w,h}` + 每页 `pageH` | 决定飞入目标位、遮罩位、入场区域；**飞入元素必须落进真实槽位**，不许悬空 |

外加：音频（BGM + SFX）、文案（标题/字卡/解说字幕）、品牌信息（字标、主色、字体）。

### 2.2 输入参数（写死在代码里的那几处）

| 位置 | 参数 |
|---|---|
| `src/index.tsx`（Composition） | `width` / `height` / `fps` / `durationInFrames` |
| `src/aifl/Main.tsx` → `AIFL_SHOTS` | 每镜的 `from` / `to`（帧区间）、场景文件；**它是时间线唯一事实源**，加删镜头只平移这里 |
| 同上 → `CAPTIONS` | 底部解说字幕的绝对帧号表 |
| 同上 → `FLASH_CUT` | 闪切转场 `from = 切点 − 5`，两侧各 5 帧跨骑接缝 |
| 同上 → SFX 钉帧表 | 30+ 条 `{from, src, volume}`，逐条对应画面动作 |
| `PageCam` 的 `keys` | `{frame, cx, cy, zoom, rotX/Y/Z, persp}` 关键帧；`zoom` 必须用 CSS `zoom` 做布局级放大（`transform: scale` 会先降采样再放大，**文字必糊**） |
| `live-layout.json` | 元素坐标（与页面 CSS px 同坐标系） |
| `props-nobgm.json` | `{"bgm": false}`，从同一时间线渲出无 BGM 版 |

### 2.3 配置项与依赖

- **运行时**：Node / npm / npx（本机 Node v22.22.2、npm 10.9.7 ✅）
- **npm 依赖**：`remotion`（必需）；`@remotion/motion-blur`（部分 demo）；`three` + `@react-three/fiber` + `@remotion/three`（仅 `FlatPanel` 与 `helpers/camera`）
- **无 API Key、无云服务**：纯本地渲染，不上传素材
- **headless 渲染三个已知坑**（README 明示，踩了会卡死）：
  1. 低核机器 `--concurrency=1`
  2. 新版 Chrome 已移除旧 headless → 必须用 `chrome-headless-shell`
  3. `remotion.media` 不通时自动下载被拒 → `--browser-executable=<本地 chrome-headless-shell>`
- **ffmpeg**：抽帧回看、音轨回测（切点误差 ≤3f）、转码 —— **本机当前没有，必须补装**

## 3. 小程序适配：三处地基必须改

这是本方案与「照着 README 跑」最关键的区别，也是唯一有技术风险的地方。

| 原假设 | 小程序现实 | 我的做法 |
|---|---|---|
| 起 dev server，Playwright 截**长全页** | 小程序无 DOM/URL；视口固定 375×812（rpx 体系） | 用**微信开发者工具模拟器**驱动真实页面（`D:\Tencent\微信web开发者工具` 已装），按 3x 出 **1125×2436** 屏图；`layout.json` 由元素选择器实测坐标生成 |
| 2.5D 相机在**整页**上推拉 | 「整页」不存在，只有一屏一屏 | 相机改为**绕手机设备环绕**：手机是主体，屏内图贴在设备框里；跨页叙事靠「多台手机并置 / 卡片飞出设备」完成 |
| 画幅即页面画幅 | 竖屏 App，成片要横屏 16:9 | 1920×1080 横画布 + 竖屏设备居中悬浮；参赛版缩到 1280×720 |

**带来的收益**：模板里最抓人的「卡片落进真实槽位」「数字里程表」「玻璃质感光扫」全部保留，因为它们作用在设备屏内，与横竖屏无关。

## 4. 成片方案

### 4.1 视觉语言：从产品自身长出来（不套 Ink Press 的纸墨琥珀）

直接从 `app.wxss` 提取，不另造皮肤：

- 底：极光渐变 `135° #EAF1FF → #DCE8FF 40% → #F3F0FF`（项目内部代号 Auroraqua）
- 面：液态玻璃 `rgba(255,255,255,.35)` + `blur(24px) saturate(180%)` + 1rpx 亮边 + 内高光
- 主色：品牌蓝 `#3370FF`；语义色 绿 `#00B42A` / 橙 `#FF7D00` / 红 `#F53F3F`
- 字：PingFang SC；标题 700、正文 400；圆角 32rpx 统一刻度

**动效性格 tokens**（按流水线的两轴推导：能量中 × 调性亲和）：
主时长 ~26f、入场 `cubic-bezier(.25,.46,.45,.94)`、过冲 1.04、squash 0.08；落定必 hold，brand 字标 ≥30f。

### 4.2 镜头结构（10 镜 / 1080 帧 / 36.0s）

能量骨架：低（开场）→ 中高（功能）与低（字卡呼吸位）交替 → 全片峰值（收尾）。

| # | 帧 | 时长 | 画面 | 镜头卡 |
|---|---|---|---|---|
| 1 | 0–200 | 6.7s | 极光暗场起，一束侧光扫过玻璃面 → 手机自虚焦浮起、屏幕点亮到「班级概况」（56/28/28 已在位）→ 字标压印 hold 30f | `brand-ink-open`（改写为光扫版）+ `spotlight-hero-card` |
| 2 | 200–252 | 1.7s | 字卡①「一个班，所有事。」 | `paper-title-card` |
| 3 | 252–430 | 5.9s | 花名册：56 张成员卡从页面飞入 3D 网格，A/B 双色分区；56 / 28 / 28 里程表逐位落定 | `deck-deal-flyin` + `DigitRoll` |
| 4 | 430–520 | 3.0s | 课表：A组/B组 **液态指示器滑动特写**（产品里最精致的动效，值得单独一拍）→ 全体课/分组课切换 | 自绘（忠于组件真实参数） |
| 5 | 520–570 | 1.7s | 字卡②「值日不用再吵。」 | `paper-title-card` |
| 6 | 570–680 | 3.7s | 值日：日历轮转 → 周卡逐周压入堆叠，今天的名字高亮 | `list-stack-press` |
| 7 | 680–730 | 1.7s | 字卡③「通知，一条不落。」 | `paper-title-card` |
| 8 | 730–840 | 3.7s | 通知：正文打字机揭示 → 发送 → 通知卡飞入列表 → 未读角标数字弹跳 | `document-typewriter-reveal` |
| 9 | 840–950 | 3.7s | 班费：余额数字滚动到 273.9 → 消费明细卡逐张飞入 → 凭证图扇形展开 | `DigitRoll` + 卡堆 |
| 10 | 950–1080 | 4.3s | 收尾：各页面缩成小卡合影 → 铅印字标砸落（riser→impact→sparkle）→ hold 1s + 小程序码 | `outro-group-photo-launch` |

**取舍说明**：作业模块（1.0.8）后端刚上线、前端未过真机验证，**建议不拍或只给 1 秒**——拍到没验证的功能是给自己埋雷。

### 4.3 转场

- 主转场：**暖白闪**（`FlashCut`）4 处，`from = 切点 − 5`，两侧各 5f 跨骑接缝——不用黑场，浅色片里黑切像断层
- 其余硬切全部**卡在拍上**（若启用 BGM）
- 页与页之间不用叠化：靠相机位移 + 主体完整动作弧自然衔接，这是「电影感来自运镜」而不是靠特效堆叠

### 4.4 配乐与声音

- **BGM**：从仓库 5 首里选（`house-vibez` / `bgm-tech-house` 优先试听，校园清爽调性）；启用则先做 **librosa 网格拟合**求真实 BPM/相位 + kick/snare/hihat 定位，网格验收通过才分镜，时间线用 `beatF(n)` 写
- **保底方案**：SFX-only（Ink Press 原版就是 36.2s 无 BGM）——36 秒的片不配乐完全立得住，且免掉卡点返工
- **SFX**：16 类里按材质取，正好对得上产品语言 —— 转场 `transition/`、落定 `impact/`、收尾 `riser→impact→sparkle`、点击 `ui/`、卡片 `paper/`、数字 `counter/`、玻璃 `glass/`；**禁游戏 UI 音色**
- **口播**：默认不配人声，用底部通栏解说字幕（`Caption`，等宽小字 + 字距）。需要人声时再单独议

## 7. 一个必须先定的问题：宣传片 ≠ 演示视频

参赛要求是「**演示视频** MP4 1280×720 ≤200MB」，截止 **2026-10-30 24:00**（还剩 2 天）。

- **纯电影感宣传片**讲的是感受，36 秒里每个功能只露 3–6 秒，评委看不到「完整业务流程」；
- **演示视频**要求功能覆盖 + 流程完整，通常 3–5 分钟，带解说。

三条路，我推荐第 2 条：

| 方案 | 说明 | 判断 |
|---|---|---|
| A. 只做 36s 宣传片 | 最漂亮，但作为参赛「演示视频」覆盖不足 | ✗ 不建议 |
| B. **36s 宣传片 + 3 分钟演示视频**（宣传片作片头，演示部分用同一套设计 tokens 的录屏 + 字幕） | 兼顾观感与完整度，宣传片资产可复用 | ✅ **推荐** |
| C. 只做 3 分钟演示视频 | 稳妥但平庸，浪费了这套工具能给的质感 | 备选 |
