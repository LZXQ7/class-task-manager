# 班级任务管理微信小程序

---

# 1 功能介绍

## 1.1 需求介绍（背景与痛点）
高校班级日常事务高度依赖微信群接龙、Excel 表格与口头通知，存在三类典型痛点：

1. **值日排班低效易错**：传统人工轮值靠班委记忆或群接龙，换课、调休、请假后极易漏排、重排、冲突；一名生活委员每周需耗费【x】小时手工编排。
2. **班费账目不透明**：收支仅靠记账本或群内公示，成员无法随时核对余额，信任成本高，历史流水难以追溯。
3. **作业与通知触达弱**：作业截止靠群 @，漏看率高；通知"已读未读"不可见，班委无法确认全员知晓，重要事项（如调课、集合）存在盲区。

本项目以"班级管理"这一真实教育管理场景为对象，**自主编程**研发微信小程序，将排班、班费、作业、通知、课程表、请假等事务统一数字化，打通"发布—执行—确认—统计"闭环。

## 1.2 应用功能介绍（按模块）

### 模块一 · 智能排班与值日（核心）
- **轮转引擎**：基于"全体课卡死回绕"三判据（ahead 空时仅从起点卡死或两组同时到尾才回绕），实现公平轮值，杜绝本组满而另组有人时的错误回绕。
- **岗位槽配置**：生活委员可自填"哪天·第几节·几人"（`duty_slot`），支持全天承包（period 为空）；空表自动回落原逻辑，对已运行班级零影响。
- **保洁专项**：18:10 主教室打扫建模为 CLEAN 课次（period=4），人数逐天可设，与常规值日隔离，关闭开关仅置零 duty_count 不删课次，避免孤儿数据。
- **排班规则**：每班一行（`schedule_rules`），支持补录窗口、免排名单（`member.duty_off`）、避免同日等策略，generate/手动/cron 多入口统一过滤。

### 模块二 · 成员与权限
- 成员档案含姓名、组别、职务、学号、绑定状态、角色（普通成员 / 班委 / 超管 / 辅导员）。
- **分级可见**：普通成员仅见姓名+组别+职务的只读视图；班委/超管可见管理视图，权限真源统一为 `util.feeRights` 等函数，杜绝越权。

### 模块三 · 班费管理
- 收支流水（收入/支出/余额），余额 = 总额 − 已消费，实时核算。
- 权限隔离：记账与导出限定班委/超管，普通成员仅可查看公开余额与流水摘要。

### 模块四 · 作业提交
- 支持图文/文件附件（单图 10MB、文件 20MB、总量 50MB、图≤9、文件≤3），过期附件由 `cron-weekly` 自动清理（PURGE 7 天）。
- **提交播报**：首页顶部滚动"某某 提交了《X》"，仅向班委/超管/辅导员展示，兼顾时效与隐私。

### 模块五 · 通知中心
- 支持按班查看（`msgList` 收 classId），目标类型 ALL / 委员会 / 按职务 / 指定人；越权静默回落。
- **确认收到**：辅导员等非收件人不显示确认；发布页读 `?classId=` 预选发送班级，防串班。

### 模块六 · 课程表与班级信息
- 首页课程表摘要："今天 N 节 · 本周 M 节"，自动排除保洁课次，A/B 分组课按本人组别计算。
- 多班切换：点班名开底部弹层选班，仅多班时渲染切换入口。

### 模块七 · 请假与远程配置
- 请假流程线上化，状态可视。
- **远程配置**（app_config）：文案与开关免审下发，改文案无需发版，降低运维成本。

### 模块八 · 数据统计与后台
- 前端埋点（`usage_event`）回流使用行为，支撑成效量化。
- 超管 Web 后台（admin-web）用于成员、排班规则、统计的集中管理。

| 埋点 usage_event | event, user_id, ts | 成效量化 |

### 1.4.2 关键表单（用户输入界面）
- 排班生成表单：适用星期（多选）、岗位、人数、是否保洁、补录窗口。
- 班费记账表单：类型、金额、备注、凭证图（班委）。
- 作业发布表单：标题、截止、附件（图/文件）。
- 通知发布表单：发送班级（?classId 预选）、目标范围、正文。

### 1.4.3 报表输出
- **排班周表**：按星期×节次呈现值日/保洁人员。
- **班费月报**：收入、支出、余额、分类汇总，可导出。
- **作业统计**：提交率、逾期名单。
- **通知触达**：已读/未读分布。
- **使用画像**：活跃用户、功能使用频次（来自 usage_event）。

## 1.5 业务流程设计
**排班生成流程**：读取课程表与岗位槽 → 快照整池 → 按轮转三判据分配 → 套用排班规则（免排/补录窗口）→ 写回 duty/shift → 前端按"星期×节次"渲染。
**班费流程**：班委提交记账（鉴权）→ 写 fee 流水 → 余额实时派生 → 成员只读视图拉取。
**作业流程**：发布（限流校验）→ 成员提交（附件落云存储）→ 提交播报（限定角色）→ 逾期 cron 统计。
**通知流程**：发布（预选班级/目标）→ 写入 notice + 目标映射 → 成员按班拉取 → 确认收到回写 → 未读可视。

## 1.6 创新点与技术特点
- **自主编程、零低代码依赖**：原生微信小程序 + 云函数（Node.js）+ 云数据库 + 云存储，全栈自研，可审计、可演进。
- **公平轮转算法**：以"卡死回绕三判据"解决多组混合轮值的公平性难题，优于人工/接龙。
- **保洁与值日双轨隔离**：CLEAN 课次建模 + 逐天人数，解决"大扫除 vs 日常打扫"长期混淆。
- **免审远程配置**：文案/开关热更新，规避发版等待，提升运维效率。
- **AI 能力预留接口**：轮转/作业/通知模块已抽象服务层，可平滑接入智能排课、学情分析、智能答疑等 AI 能力（赛道鼓励方向）。

## 1.8 隐私保护与安全合规设计（重点）

本项目处理真实校园数据，其中包含**学号、微信 openid、绑定状态、角色与权限标识**等个人敏感信息（PII）。因此，本项目将"**隐私保护优先**"作为底层设计原则，而非事后补救——从数据建模、接口下发、权限判定到代码提交与对外材料，全链路内置隐私保护机制。具体设计如下：

### 1.8.1 隐私字段分级与最小化收集
- **PII 字段（敏感，限制使用）**：`student_no`（学号）、`openid`（微信身份）、`bound`（绑定状态）、`role`、`is_super`（权限标识）。这些字段仅在鉴权与管理视图内部使用，**绝不向无关前端下发**。
- **非 PII 字段（班级内公开）**：`name`（姓名）、`group_name`（组别）、`position`（职务）属于班级内部公开信息，普通成员可见。
- **最小化接口**：普通成员的只读视图接口（`member.list` 的 `read` 分支）**仅返回** `姓名 + 组别 + 职务 + readOnly 只读标记` 四个字段，明确**不返回**学号、openid、绑定状态、角色、超管标识。未绑定人数等敏感统计也按角色脱敏（如 `boundCount` 对只读态返回 `null`，避免"全班未绑定"的误判红字）。

### 1.8.2 基于角色的细粒度权限（权限真源统一）
- 所有权限判定收敛到统一函数（如 `util.feeRights`，且前端 `fee` 鉴权逻辑与后端**逐字一致**），避免权限判定散落在各页面导致的越权漏洞。
- 跨班操作统一经 `guard.resolveClassId` 解析班级边界，**禁用** `classIdOf` 直接取值，从机制上防止串班读取他班数据。
- **越权静默回落**而非报错抛异常：超管在自己班发布的通知不会串到他班；普通成员越权查看时仅返回空数据，不暴露系统结构与报错信息，既安全又不影响体验。

### 1.8.3 演示态与数据脱敏机制（提交与外展示专用）
- 系统内置**演示态（演示账号）**：评审、对外展示、视频录制均可使用脱敏演示账号，无需暴露真实班级与个人信息。
- **公开/私有双仓机制**：含真实 PII 的代码存于私有仓库；对外提交的源码取自**已脱敏的公开仓库**。脱敏由 `scrub.js` 完成，其 `TEXT_EXT` 覆盖所有源码扩展名（含新增的 `.mjs`，曾因漏覆盖导致脱敏失效），密钥绝对路径规则排在 AppID 之前，杜绝密钥与隐私明文入库。
- **对外材料脱敏**：说明文档 PDF 与演示视频分镜均使用脱敏演示账号与 `【】` 占位数据，**不展示真实姓名、学号、openid**；录屏与截图一律以演示账号或模拟图替代真实数据。

### 1.8.4 凭据与运行安全
- 云函数数据库凭据（`DB_*` 环境变量）通过部署脚本从 `.env-course` **注入后即还原**，绝不以明文残留在 `cloudbaserc.json` 或源码中；单函数更新使用 `tcb fn code update`，避免按全量重发导致凭据被清空。
- 应用依托微信平台与云开发托管，数据链路加密；密钥使用绝对路径规则并前置校验，规避误提交与明文泄露。

### 1.8.5 合规底线
- 作品**原创**、基于教育真实需求开发，引用均注明出处，无抄袭与虚假信息。
- **未参与其他全国性比赛**，符合"已参与其他全国性比赛的作品不得重复参赛"的硬性要求。
- 全套提交包（源代码 zip + 说明文档 PDF + 演示视频）均经脱敏，可安全对外公开与评审。

# 2 使用手册（面向最终用户）

## 2.1 注册与登录
1. 微信搜索/扫码打开「班级任务管理」小程序。
2. 首次进入点击**微信一键登录**，授权获取微信身份（openid）。
3. 按提示**绑定班级**并填写**学号、姓名、组别、职务**（由班委或超管审核/导入）。
4. 绑定成功后进入首页；未绑定者仅见登录引导，无法查看班级数据。

## 2.2 首页概览
5. 首页顶部展示**课程表摘要**（今天 N 节 · 本周 M 节）与**作业提交播报**（班委/超管可见）。
6. 中部为功能入口：排班、班费、作业、通知、课程表、请假、班级信息。

## 2.3 排班 / 值日（成员侧）
7. 进入「排班」查看本周值日与保洁安排（按星期×节次）。
8. 若被安排，可在节点**确认**；调课/请假后由班委重排，无需手动接龙。

## 2.4 班费（成员 / 班委）
9. 成员：进入「班费」查看实时**余额**与**流水摘要**。
10. 班委：点击**记账**，选择收入/支出、填写金额与备注、可传凭证图，提交后全员可见更新。
11. 月末可在后台导出**班费月报**。

## 2.5 作业（学生 / 班委）
12. 学生：进入「作业」查看任务与截止时间，点击**提交**，上传图片（≤9）或文件（≤3，单文件≤20MB）。
13. 班委：发布作业并附附件；可在统计中查看**提交率与逾期名单**。

## 2.6 通知（全员）
14. 进入「通知」按班查看消息；重要通知点击**确认收到**。
15. 班委发布时选择**发送班级**与**目标范围**，避免串班。

## 2.7 课程表与班级切换
16. 进入「课程表」查看本人课次（A/B 分组按本人组别）。
17. 多班用户点**班名**打开底部弹层切换班级。

## 2.8 请假
18. 进入「请假」填写起止时间、事由，提交后状态可视，班委/辅导员可审批。

## 2.9 班级管理（班委 / 超管）
19. 班委/超管可在后台配置**排班岗位槽、排班规则、成员免排、远程文案**。
20. 超管通过 admin-web 集中管理多班数据与统计。

## 2.10 常见问题与注意事项
- **Q：登录后空白/提示加载失败？** A：多为网络或绑定未完成；请确认已绑定班级，并在微信内重试。
- **Q：看不到班费明细？** A：普通成员仅见余额与摘要；明细限班委/超管，属正常权限设计。
- **Q：排班为什么没我？** A：可能已在「免排名单」或当日无课次；请联系生活委员核对。
- **Q：作业附件传不上？** A：单图≤10MB、单文件≤20MB、总量≤50MB、图≤9/文件≤3；视频不在白名单。
- **注意事项**：账号与微信绑定，勿共用；班委记账须真实准确；**隐私字段（学号、openid 等）不对外截图传播，不在群聊泄露他人信息**——本应用也仅在最小必要范围内展示个人信息（详见 1.8 节）。
