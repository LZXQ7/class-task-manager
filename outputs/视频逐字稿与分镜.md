# 演示视频逐字稿与分镜（详细版）

> 本文件为「班级任务管理」微信小程序参赛演示视频的**完整制作底稿**，与主申报文档《班级任务管理-数字化应用场景创建-申报材料.md》配合使用。
> - 主文档第三章仅作索引，视频内容（逐字稿 + 分镜）**全部在本文件**。
> - 目标产出：一段 **MP4（H.264）、1280×720、≤15 分钟、≤200MB** 的演示视频。
> - 推荐总时长约 **13–14 分钟**（分镜合计），留出剪辑余量。
> - 文中 `【】` 为可量化占位，录制前请替换为真实数据；**所有画面均须使用脱敏演示账号，不得出现真实姓名、学号、openid**。

## 一、视频硬规格与录制指引

### 1.1 硬规格（务必遵守）
| 项目 | 要求 |
|---|---|
| 封装/编码 | **MP4（H.264 视频 + AAC 音频）** |
| 分辨率 | **1280×720**（16:9，导出前确认无黑边） |
| 时长 | **≤15 分钟**（本分镜约 13–14 分钟） |
| 体积 | **≤200MB**；超出时把码率压到 2–4 Mbps |
| 帧率 | 25/30 fps 均可，保持全程一致 |
| 字幕 | 非强制，但建议为主环节加字幕，提升评审观感 |

### 1.2 录制方案建议
- **主画面来源**：优先用**微信开发者工具"模拟器"录屏**（界面清晰、可操作、稳定）；或用**真机 + 电脑采集**（画面更真实但需固定机位）。
- **录制工具**：开发者工具自带录屏 / OBS Studio / 系统录屏（Win+G、macOS 快捷键 Shift+Cmd+5）；手机端用系统自带录屏。
- **配音方式**：推荐**现场口播**（对照本逐字稿，最自然）；也可先录屏、后期配旁白。口播时语速适中，重点处放慢、加重。
- **剪辑拼接**：每镜可分段录制、后期剪辑拼接，避免长停顿；转场用简单淡入淡出或硬切即可，避免过度特效。
- **导出设置**：剪映 / Premiere / HandBrake → 自定义 1280×720、H.264、码率约 3 Mbps、声道 AAC、采样 44.1kHz。

### 1.3 隐私与脱敏提醒（重要）
- 录屏、截图**一律使用脱敏演示账号**（项目已内置演示态）；不得出现真实姓名、学号、openid、真实班级全称。
- 痛点对比图（场景 2）可用**模拟图/打码图**，不打真实隐私。
- 数据看板（场景 7）用 `【】` 占位动画或脱敏数据，不展示真实学号与学生清单。
- 录制完成后，上传前再逐镜核对：凡出现真实 PII 的镜头必须替换或打码。

### 1.4 录制前检查清单
- [ ] 微信开发者工具已登录，演示账号数据已准备好（脱敏）。
- [ ] 录屏分辨率设为 1280×720，音轨测试正常。
- [ ] 逐字稿已熟读，关键数字 `【】` 已替换为真实值。
- [ ] 各功能页面（排班/班费/作业/通知/课程表）实测可操作，无报错。
- [ ] 结束页、架构图素材已备好。

## 二、逐字稿（口语化，含语气与画面）

> 使用说明：每段含【时间轴】【画面】【语气】【旁白（逐字）】【剪辑/字幕提示】。旁白可直接照读，也可在保持原意下自然发挥。

### 场景 1 · 开场（00:00–01:00）
- **画面**：黑场淡入 → 小程序图标与名称「班级任务管理」静态 2 秒 → 切到首页实机画面（课程表摘要 + 功能入口），稳定展示 2–3 秒。
- **语气**：自信、亲切，像把作品介绍给朋友。
- **旁白**：
  > 大家好，我是「班级任务管理」微信小程序的开发者。今天带大家看看，我是怎么用自主编程，把一个高校班级每天乱糟糟的事务，变成手机里一目了然的数字系统的。
  > 这个作品参加的是「数字化应用场景创建」赛道——简单说，就是用代码搭建一个真正能用在教学管理场景里的应用。它现在已经在【N】个班级、【M】名同学手里，每天真实地在用。
- **剪辑/字幕提示**：开场字幕打作品名与赛道名；首屏停留足够长，让评委看清首页布局。

### 场景 2 · 需求痛点（01:00–03:00）
- **画面**：左侧放微信群接龙截图、Excel 排班表特写（用模拟图/打码）；右侧对应小程序模块卡片（排班/班费/通知）逐一浮现，形成对照。
- **语气**：共情、略带调侃，"你是不是也经历过"。
- **旁白**：
  > 先说痛点。很多班级的值日排班，靠班委拿张纸、或者群里接龙，调一次课就得重排，经常漏人、撞人。班费呢？记在小本本上，同学想看余额还得私聊生活委员。作业和通知更头疼——群里 @ 所有人，总有人漏看，重要事情没法确认"谁收到了"。
  > 这些都不是什么大事，但天天发生，特别消耗班级精力。我的目标，就是把它们一次性搬进手机，让班级管理这件事，变得简单、透明、可追溯。
- **剪辑/字幕提示**：痛点三连（排班/班费/通知）各配一行字幕；右侧卡片用缩放/淡入强调"对应解决方案"。

### 场景 3 · 功能演示 · 排班（03:00–06:00）
- **画面**：进入「排班」页 → 展示星期×节次矩阵 → 点「一键生成」按钮 → 展示轮转结果填充动画；再进入岗位槽配置演示"哪天·第几节·几人"，并演示保洁专项（CLEAN 课次、逐天人数）。
- **语气**：讲解清晰、边点边说，突出"公平"与"自动"。
- **旁白**：
  > 核心功能是智能排班。你看这个矩阵，星期是横轴、节次是纵轴，每个人在哪天值日，一目了然。
  > 背后是一套轮转算法——公平轮值，调课、请假之后不会乱套。生活委员还能用"岗位槽"自己定：哪天、第几节、要几个人；保洁单独建模，大扫除和日常打扫不再混在一起。
  > 以前手工排，一个生活委员每周要花【A】小时；现在一键生成，只要【B】分钟。公平，而且省事。
- **剪辑/字幕提示**：重点放慢"一键生成"那一刻，给矩阵填充特写；保洁专项单独切一个 3–4 秒镜头，强调"逐天人数可设"。

### 场景 4 · 功能演示 · 班费（06:00–08:00）
- **画面**：班费页展示余额与流水摘要 → 切到班委「记账」表单填写（选收入/支出、金额、备注、传凭证图）→ 提交后余额数字实时刷新跳变。
- **语气**：强调"透明""信任"。
- **旁白**：
  > 班费模块，让账目透明。每个成员随时能看余额和流水摘要；班委记账，收入支出实时核算，月末还能导出月报。
  > 钱的事清楚了，班级的信任成本就下来了——不用再有人怀疑"班费去哪了"。
- **剪辑/字幕提示**：提交前后给余额数字一个"跳变"特写；可叠加一行字幕"余额实时核算"。

### 场景 5 · 功能演示 · 作业与通知（08:00–10:30）
- **画面**：作业发布页填标题/截止/附件 → 学生端提交（上传图片/文件）→ 回到首页看"提交播报"滚动；再演示通知：发布选班级 → 成员「确认收到」→ 展示未读分布。
- **语气**：节奏稍快，突出"触达"。
- **旁白**：
  > 作业支持图文附件，同学提交之后，首页会给班委滚动播报"谁交了"——谁没交，一眼就知道。
  > 通知可以按班、按人发，成员「确认收到」，班委一眼看到谁还没看。再也不用猜"他到底知不知道这件事"。
- **剪辑/字幕提示**：首页播报滚动给 2–3 秒特写；通知"未读分布"用图表强调"已读可视"。

### 场景 6 · 功能演示 · 课程表与多班（10:30–11:30）
- **画面**：课程表摘要"今天 N 节·本周 M 节" → 点班名打开底部弹层 → 切换班级，展示辅导员跨班统管能力。
- **语气**：轻松。
- **旁白**：
  > 课程表自动汇总，多班用户点一下班名就能切换；辅导员也能跨班统一查看排班和通知。一个入口，管全班、管多班都行。
- **剪辑/字幕提示**：底部弹层展开动作要清晰，给 1–2 秒停留。

### 场景 7 · 应用成效（11:30–13:00）
- **画面**：数据看板/报表截图轮播（排班周表、班费月报、作业提交率、通知触达率）+ 文字占位数据动画（数字从 0 跳动到 `【】` 值）。
- **语气**：实在、用数字说话。
- **旁白**：
  > 成效方面，我用数据说话：覆盖【N】个班、【M】人；排班耗时从【A】小时降到【B】分钟；作业提交率【R】%；通知确认率【C】%；服务可用率【99.X】%。
  > 它不是个 Demo，是天天在跑的真系统。
- **剪辑/字幕提示**：每个数字单独给字幕并配跳动动画；报表页切换要稳，别太快。

### 场景 8 · 技术与创新 + 结语（13:00–14:00）
- **画面**：技术架构简图（小程序 + 云函数 + 云数据库 + 云存储，画成三层/四块）→ 回到小程序图标 → 结束页（致谢 + 欢迎体验）。
- **语气**：收束、留余味。
- **旁白**：
  > 技术上，它是原生小程序加云函数全栈自研，没有用低代码糊弄；还预留了 AI 接口，将来能接智能排课、学情分析。
  > 一个班级的小工具，背后是真实需求、完整闭环，和一点点工程上的坚持。谢谢大家，也欢迎评委老师实际体验。
- **剪辑/字幕提示**：架构图静态展示 3–4 秒，标注四层；结束页停留 2 秒。

## 四、录制流程与上传自检清单

### 4.1 推荐录制流程
1. **准备素材**：演示账号数据、架构图、结束页、模拟痛点图。
2. **分段录制**：按 8 个场景分别录制，单镜可多拍几条备选。
3. **后期剪辑**：拼接 8 镜，统一 1280×720，加必要字幕与转场。
4. **导出**：H.264 / 1280×720 / 码率 ~3 Mbps / AAC，生成 MP4。
5. **核对**：逐镜检查隐私（无真实 PII）、总时长 ≤15 分钟、体积 ≤200MB。

### 4.2 上传前自检清单
- [ ] 成片分辨率确为 **1280×720**，无黑边、无拉伸。
- [ ] 总时长 **≤15 分钟**。
- [ ] 文件体积 **≤200MB**（超出则降码率重导出）。
- [ ] 逐镜确认**无真实姓名、学号、openid** 出现（演示账号/打码/模拟图）。
- [ ] 关键数字 `【】` 已替换为真实数据，且与说明文档 1.7 节口径一致。
- [ ] 音频清晰、无杂音，旁白与画面同步。
- [ ] 结尾含作品名与致谢，便于评委识别。

> 备注：如暂无法真机/模拟器录制，可先用幻灯片（按本分镜 8 页）+ 旁白生成一版占位 MP4 应急；但**正式评审建议用真实小程序录屏**，更能体现功能完整度与成效。
