## 第 1 步 · 生产库变更（必须最先做）

### 1.1 先只读探测，核对现状

```sql
SELECT s.id, s.class_id, s.day_of_week, s.period, s.duty_count, s.kind,
       c.id AS course_id, c.name AS course_name, c.room
  FROM session s JOIN course c ON c.id = s.course_id
 WHERE s.kind = 'CLEAN'
 ORDER BY s.class_id, s.day_of_week;
```

期望：5 条 CLEAN（周一~周五，第 4 节），全部指向「打扫410」、`duty_count = 2`。
如果某个班的周二那条不存在，下面的迁移对它无效（需先补课次）。

### 1.2 执行迁移

**推荐脚本**：`scripts/migrate-tuesday-clean.sql`（**纯 DML，无 DDL**）。

```bash
bash scripts/run_sql_file.sh scripts/migrate-tuesday-clean.sql
```

或逐条执行（脚本内容原文）：

```sql
SET @owner_id = (SELECT COALESCE(
  (SELECT id FROM member WHERE is_super = 1 ORDER BY id LIMIT 1), 13));

INSERT INTO course (name, teacher, room, course_type, duty_count, created_by)
SELECT '410大扫除', NULL, '410', 'ALL', 4, @owner_id
  FROM DUAL
  WHERE NOT EXISTS (SELECT 1 FROM course WHERE name = '410大扫除');

UPDATE session s
  JOIN course c_from ON c_from.id = s.course_id
  JOIN course c_to   ON c_to.name = '410大扫除'
   SET s.course_id  = c_to.id,
       s.duty_count = 4
 WHERE s.kind = 'CLEAN'
   AND s.day_of_week = 2
   AND s.period = 4
   AND c_from.name = '打扫410';

UPDATE session s
  JOIN course c ON c.id = s.course_id
   SET s.duty_count = 4
 WHERE s.kind = 'CLEAN'
   AND s.day_of_week = 2
   AND s.period = 4
   AND c.name = '410大扫除'
   AND s.duty_count <> 4;

UPDATE course SET duty_count = 4 WHERE name = '410大扫除' AND duty_count <> 4;
```

> （2026-10-10 实测 `CREATE command denied to user 'classassist_app'`）。
> 任何 `CREATE TABLE` / `ALTER TABLE` 都会直接报错。

（否则周二同学收到的通知仍会写「打扫410」）。

> ⚠️ 用 `fn code update`（**更新已有函数**）。**不要**用 `tcb fn deploy`——
> 那会应用 `cloudbaserc.json` 并可能覆盖环境变量与触发器。
> ⚠️ `-e` 后面是**环境 Id**，不是字面 `env`。
> ⚠️ 部署前确认 `cron-weekly/config.json` 的 5 个触发器与线上一致
> （`tcb fn detail cron-weekly -e <YOUR_ENV_ID>`）——
> 云函数 `triggers` 是**整体覆盖**语义，漏一条就等于删掉它。

**不需要重部署**：`schedule` / `duty` / `export` / `admin-web`。
它们的人数与课程名都是运行时读库，没有按星期二写死的分支。
