# 自动排班规则 与 后台操作指引

> 适用版本：MVP v1.0 · 2026-09-23
> 一句话：**「后台」就是云数据库 + 云函数，但你不用打开任何外部后台——所有增删改都在小程序里，用管理员账号点几下就行。**

---

## 一、「后台」到底是什么

小程序本身不能直接存数据（会被卸载即丢），所以数据放在腾讯云开发（CloudBase）里。三层结构：

| 层 | 是什么 | 你要不要碰 |
| --- | --- | --- |
| **小程序（前端）** | 你手机上看到的 6 个页面 | ✅ 所有操作都在这里 |
| **云函数（接口层）** | 11 个后端函数，负责校验身份、算排班、写数据库 | ❌ 不用碰，已部署好 |
| **MySQL（数据层）** | 14 张表：成员、课程、课次、值日、请假、公告… | ❌ 不用碰，已建好并灌了演示数据 |

> 演示数据：12 名同学（张伟…孙丽，学号 20260101–20260112）、4 门课 / 4 节课次、第 1、2 周值日。**换成你们班的真实名单后即可正式使用。**

关键点：**「添加课程表 / 值日表」不是去网页后台录入，而是在小程序里以管理员身份操作。**

---

## 二、准备：先把自己设成管理员

只有「管理员 / 班长」角色的账号在课表和值日页才能看到增删按钮。首次部署时，第一个绑定的人需要在数据库把 `member.role` 从 `MEMBER` 改成 `ADMIN`（或 `MONITOR`），其余同学**不需要**任何设置。

云函数层还有 `needAdmin` 兜底：即使有人绕过前端，非管理员调接口也会被拒。

## 三、三步搭起整学期的课表

### 第 1 步 · 导入名单（决定 A / B 分组）

路径：**我的 → 成员与分组 → 导入名单**

按行粘贴，每行一条：

```
张伟,20260101
李娜,20260102
王芳,20260103
```

- 分组**自动**判定：**学号尾号单数 = A 组，双数 = B 组**（无需手填）
- 上方也支持用口令换取班级名单
- 非管理员看不到这个入口

### 第 2 步 · 添加课次（课表的最小单位）

路径：**课表 → 右下角「+」（管理员可见）**

每个字段的含义：

| 字段 | 说明 |
| --- | --- |
| 课程名 / 教师 / 教室 | 课次显示用 |
| **课程类型** | `全体课`（全班一起上）或 `分组课` |
| **上课分组** | 选「分组课」时才出现：**A 组** 或 **B 组** |
| 上课时间 | 周几（周一–周日，含周末，方便调休补课）+ 第几节（1–2 上午 / 3–4 下午 / 5 晚上） |
| 上课周次 | **多选** 1–16 周；一个都不勾 = 每周都上 |
| 需值日人数 | 默认 **2**（＝每节课下课安排两人） |

> ⚠️ 「周次」和「分组」是两件不相干的事：
> **周次**＝这学期第几周上课；**分组**＝谁来上这节课 / 谁来打扫。
> 所以「A 组的课」就选 `分组课 + A 组`，不要管周次。

### 第 3 步 · 生成值日并发布

路径：**值日 → 「一键生成」 → 「发布给全班」**

- **一键生成**：按下面的轮转规则，为本周每个课次各排出 2 人；只覆盖自动排的部分，**已手动换人的记录保留**
- **发布给全班**：发布前只有管理员能看到草稿；发布后全班可见，并触发订阅消息
- 想改某一条：点该条值日 → 手动换人（原值日标记为「已换出」，不影响别人）

## 四、自动排班规则：按学号轮转

### 排序规则（算法核心）

对每一次课，从**候选池**里按这个顺序挑 `duty_count` 个人（默认 2 人）：

1. **候选池**：该课次对应分组里的在册同学（全体课 = 全班），排除当天已排过的人、当天请假的人
2. **本轮优先**：优先取**本轮还没排过**的人
3. **排序**：先比 **本轮已排次数**（少的优先）→ 次数相同再比 **序号**（靠前的优先）
4. 取前 N 名

因为每排一次就把该同学的次数 +1，所以**同一天同一组的课会沿着序号一路往下轮**。

### 两个必须记住的语义

- **一轮里每人只排一次**：同一个人**不会在同一周出现两次**，哪怕是在不同的两天。
  周一排过的同学，周三不会再被排到（除非本周名额多过可用人数，属于最后手段，会在告警里提示）。
- **跨周接着往下排**：本周排到 40 号，下周第一节课就从 41 号继续；
  **全班 56 人都轮过一遍之后，重置标记，再从 1 号开始**。

也就是「按序号发号，一路往后走，走完一圈回到 1 号」。下面是 6 周的实跑结果（每周 40 个名额）：

| 周次 | 值日序号 | 说明 |
| --- | --- | --- |
| 第 1 周 | 01 ~ 40 | 从 1 号开始连续取号 |
| 第 2 周 | 41 ~ 56，然后 01 ~ 24 | 接着上周继续；50 号以后没号了 → **重置标记回到 1 号** |
| 第 3 周 | 25 ~ 56，然后 01 ~ 08 | 第二轮已经用到 24 号，所以从 25 号继续 |
| 第 4 周 | 09 ~ 48 | 依此类推 |

6 周下来每人排 4~5 次，**最多的人和最少的人只差 1 次**。

### 用你的例子验算（12 人班，尾号奇 A / 偶 B）

一天四节课：上午 A 组两节，下午一节全体课 + 一节 B 组课。

| 节次 | 课次类型 | 安排值日 | 为什么是这两个 |
| --- | --- | --- | --- |
| 第 1 节 | A 组课 | **1 号、3 号** | A 组 {1,3,5,7,9,11} 次数都是 0，序号最靠前的两个 |
| 第 2 节 | A 组课 | **5 号、7 号** | 1、3 的次数已变 1，剩 {5,7,9,11} 里最靠前的两个 |
| 第 3 节 | 全体课 | **2 号、4 号** | 全班里 1、3、5、7 次数已是 1；次数 0 的人中 2 号序号最靠前，其次 4 号 |
| 第 4 节 | B 组课 | **6 号、8 号** | B 组里 2、4 次数已变 1；次数 0 的 {6,8,10,12} 里最靠前的两个 |

✅ 与你的预期完全一致。这一结果已用离线仿真脚本逐行验证过，可随时复跑：

```bash
node scripts/check-duty-rotation.js   # 用你给的真实课表 + 真实名单对照
node scripts/check-round-robin.js     # 连续 6 周仿真：不重复 / 接着排 / 满一轮重置
```

两个脚本都是**从生产源码里抽出算法本体**跑的（不再各自复制一份算法），
所以它们测的就是线上真正在跑的那份代码。改动排班逻辑后请重跑，防止回归。

### 「谁配到哪节课次」由程序决定（2026-09-24 定稿）

值日页「一键生成」弹层里有两条路：

| 按钮 | 它做什么 |
| --- | --- |
| **按序号轮转** | 纯本地算法，全班按上面的规则从头轮转 |
| **AI 生成** | **同一套本地取号算法** + 用 DeepSeek 听懂你那句话（哪些课次别动、哪些人本轮跳过） |

关键点：**AI 不决定「谁配到哪节课次」**。它给出的人选只作参考，最终配对一律由程序
按「课次先后顺序（日期 → 节次）+ 取最小可用序号」重排。所以：

- 同一个输入永远是同一个结果，不会「这次 50 号排周一、下次排周四」；
- **同一个分组内，后一节课的序号一定大于前一节课** —— 也就是你要的「一路往后排」；
- AI 写的顺序偏了会在告警里说明（「AI 建议的 xx 号与顺位不一致，已按序号顺序重新配对」）。

为什么不让 AI 决定配对 —— 它真的会给一个「人挑对了、顺序配错了」的答案。实测那次输入
「A 组 23 号之前全部排过了，B 组 24 号之前全部排过了」：AI 挑的 24 个人**完全正确**
（A 组最小的 10 个、B 组最小的 14 个，两两不重复），却把 B 组最后两个号
（50 示例成员50、52 示例成员52）配给了**最早的** B 组课（周一第 4 节），把 46、48 留到最晚的周四第 5 节。
现在周一第 4 节必然是最小的可用 B 组号（30 示例成员30、32 示例成员32）。

```bash
node scripts/check-seq-order.js   # 用那次真实输入 + 真实课表钉住顺序（36 项断言）
```

### 边界情况

- **某天同组课太多**：比如 A 组 6 人，一天有 4 节 A 组课 → 需要 8 人，人手不够。此时**不会报错**，而是少排，并在生成结果里返回 `SHORTAGE` 警告（提示「周X第N节候选不足（还需 K 人）」）。
- **不受次数上限约束**：值日次数只用于排序、不设上限，长期轮转自然均衡。
- **课程值日与保洁共用同一个轮转池**：同一周里已经在某节课值日的同学，不会再被排进「打扫 410」；
  反过来也一样。两者合起来一周约 40+10 个名额，所以每个人大约两周轮到一次。

## 六、临时调课（按周改课表，只影响点名的那几周）

### 6.1 它和「校历调课」的区别

这两种东西常常被混为一谈，但它们解决的是不同层级的问题，而且**可以叠加**：

| | 校历 · 按天调课 | 临时调课 |
| --- | --- | --- |
| 入口 | 课表右上角「校历」 | 课表右下角「临时调课」/ 长按格子 |
| 粒度 | **一整天**的所有课次 | **一节课这一周**的例外 |
| 存储 | `day_shift`（from_date → to_date） | `session_shift`（session_id + week） |
| 典型场景 | 台风停课，周四整天挪到周六 | 老师出差，周三第 5 节这周改到周五第 1 节 |

两者的解释都由同一个函数完成（`common/week.js` 的 `resolveSlot`）：
**先看临时调课（可能整条取消、或换到别的格子）→ 再看按天调课 → 最后看法定放假。**

### 6.2 四种用法

1. **长按格子**（最快）
   在课表格子上长按 → 自动弹出「临时调课」并选中那节课，默认「这一周不上」。
   需要改时间就切到「改到别的格子」，再选周几 + 第几节。
2. **多周次**
   切到「多周次」，选课次 → 选操作 → 勾选要应用的周次（可多选）→ 应用。
   适合「接下来三周这节课都不上」这类连续调整。
3. **按日期**
   - 「这几天不上课」：选中本周要取消的日期（可多选，一整天所有课都不上）
   - 「某天调到另一天」：和校历的按天调课等价，整天挪走，可跨周
4. **AI 调课**
   用一句话描述，例如「这周四第 3 节不上」「周三第 5 节的音乐基础改到周五第 1 节」
   「周五的课全部不上」。AI 只负责把你的话翻译成「哪几节课怎么办」，
   课次是否存在、目标格子是否合法、有没有撞车，全部由本地规则判定。
   生成后先给**方案预览**，确认无误再「应用到第 N 周」。
   点「链路自检」可以确认 DeepSeek 通道是否正常。

### 6.3 调课会连带改什么（重要）

- **值日会跟着走**：改时间的课次，已排的值日日期同步改到新日期，人不变；
  「本周不上」的课次，未完成的值日会被删除（已完成 / 已请假的留作历史记录）。
  如果值日跟着挪过去会撞上某位同学当天的另一条值日，那条会被删掉，
  需要你到「值日 → 手动排班」补人。
- **已发布的周会退回草稿**：课表变了但班级还看到「已发布」，就会出现「课表和值日对不上」。
  所以调课之后本周若原本是 PUBLISHED，会自动退回 DRAFT，需要重新点「发布」。
- **撤销会把日期改回去**：在「结果」里撤销（或撤销本周全部），课表和值日一起恢复原样。
- **撞车只提醒不拦截**：如果目标格子已经有别的课，会弹窗提示是哪两门课，
  但操作仍然会生效 —— 临时调课是你有意为之的一周例外，系统不该替你否决；
  请自己确认后再决定要不要留。

### 6.4 权限

临时调课与校历同级，**仅超级管理员**可用（示例成员01）。普通管理员看不到右下角的
「临时调课」入口，长按格子也只会得到一句提示。
