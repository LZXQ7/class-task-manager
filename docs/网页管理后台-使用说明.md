# 网页管理后台 · 使用与运维说明

> 建立于 2026-10-10。面向**超级管理员**，公网访问，与小程序端同一套数据库。
> 本文件只写「怎么用 / 怎么维护 / 出事了怎么办」，实现细节在代码注释里。

---

## 一、这是什么

给超管用的**网页管理后台**，用来替代以前「本地脚本解析 xlsx → SQL 直插」那套土办法。
首批功能：课程表（查看 / xlsx 导入 / 改课次）、成员管理、账号班级配置、系统配置（后台账号）、操作审计。

**排班与请假不在第一批**（语义最重、漂移代价最高，留到第二批）。

### ⚠️ 若「点登录没反应」——先看这一条（2026-10-10 真实故障，已修）

历史上出过这么一次，症状是：**点「登录」按钮，页面毫无反应**。
根因是 `gatewayPath="/admin"` 让网关**只转发 `/admin` 前缀**，
而页面当时把 JS/CSS 写成了根路径 `/app.js`、`/admin.css` ⇒ 两个资源全 404
⇒ `app.js` 一行没执行 ⇒ 登录表单的 `submit` 事件没绑上 ⇒ 点按钮退化成
**浏览器原生表单 GET 提交**，页面原地刷新、什么提示都没有。

**这个故障的恶劣之处**（记住，别再犯）：
1. **看起来完全正常** —— 页面照样渲染得一模一样，只是不响应点击。
2. **口令会被拼进 URL**（`?username=…&password=…`）落进浏览器历史记录。
3. **本地 e2e 43 项全绿** —— 因为 e2e 跑 `127.0.0.1` **根路径**，
   测的根本不是线上这套路径形态。**本地绿 ≠ 线上可用。**

已修（代码 + 门禁双保险）：
- 前端资源与 API 统一带 `/admin` 前缀，且前缀**从 `location.pathname` 运行时推导**（不写死，否则本地 e2e 会全挂）；
- 服务端静态资源挂 `/admin` 前缀、API 前缀归一化回 `/api/*`，兼容线上（网关已剥前缀）与本地（没剥）两种形态；
- SPA 兜底**排除带扩展名的请求** —— 资源 404 必须原样 404，绝不能拿首页 HTML 冒充 JS（否则报 `Unexpected token '<'`）；
- **本地 e2e 改为从 `/admin` 进入**，路径形态与线上一致；
- 新增门禁 `check-admin-gateway-prefix`（31 项，含 6 组变异自证）。

**每次部署 admin-web 后必须跑线上验证**（不要只跑本地 e2e）：
```bash
ADMIN_PASS=<口令> node scripts/verify-admin-web-online.js
```
它会穿风险页、验资源真加载、**点一下按钮确认真的发出了 `/api/auth/login`**、
校验 URL 没被拼上口令、再做一次真实登录。**13 项。**

### 使用前提（真源口径，改了会立刻掉线）

后台账号 `admin` 绑的是成员 **id=13 示例成员01**。
后台权限的**唯一真源是 `member.is_super=1` 且 `status='ACTIVE'`**，
所以在小程序里把这个人取消超管或停用，网页后台**下一次刷新就会掉线**。
这是刻意的：避免 `admin_user` 表变成绕过成员状态的后门。

## 三、功能速查

### 课程表
- 顶部选班（后台**跨班放开**，不像小程序那样锁本班）。
- `全部 / A 组 / B 组` 三个视图。**A 组视图 = 本组课 + 全体课**（与小程序课表页口径一致）。
- **导入课表**：先选组别，再传 xlsx → 弹出**干跑预览**（目标班级名 + 影响行数 + 是否会降为全体课）→ 确认后才写库。
  - 写库前自动建 `bak_session_<时间戳>` / `bak_course_<时间戳>` 备份表。
  - 规则：同组 COURSE 课次**整体覆盖**；保洁（CLEAN）课次**不动**；A/B 重复的课**自动降为全体课**。
  - 已发布的周次会**退回草稿**，需在小程序端重新发布。
- **改课次**：改单节课的星期/节次/周次，保存时同样把该班已发布周次退回草稿。

### 成员
- 搜索姓名或学号；新增 / 编辑 / 删除 / 设为超管。
- **测试账号（学号 0000000000 段）一律不显示**，包括超管。这是项目铁律，不是可配置项。
- 有值日或请假历史的成员**不可硬删**，系统会提示改用「停用」。
- 「不排值日」在列表的「值日数」列直接标出来。

### 账号班级
- 改班级名 / 学期起始 / 总周数 / 绑定开关 / 大节时间。
- 显示班级口令与邀请码。

### 系统配置
- 后台账号列表，含**有效态**判定（后台已启用 **且** member 是超管 **且** member 状态正常）。
  三个条件任一不满足即显示「不可用」——这是防后门的可视化。
- 改密码 / 停用需**当前密码二次校验**。

### 操作审计
- 记录谁在什么时候对哪个班做了什么。审计写入失败**不阻断业务**（宁可少一条日志，也不能让用户以为操作失败而重复提交）。

## 四、运维

### 重新部署

```bash
# admin-web：走 cloudbaserc.json 声明式收敛（函数 + 网关路由一起）
tcb deploy --only functions
tcb deploy --only gateway

# 其余 13 个事件函数（改了 common/ 之后必须全量）
bash scripts/deploy_all.sh
```

配置真源是仓库根的 **`cloudbaserc.json`**（函数类型 / 超时 / 内存 / VPC / 网关路径都在里面）。

### 部署这块踩过的坑（别重复踩）

| 现象 | 真因 | 正解 |
|---|---|---|
| `× path must start with /` | Git Bash 把 `--path /admin` 改写成 Windows 路径；`MSYS_NO_PATHCONV=1` **实测无效** | 用 `cloudbaserc.json` 的 `gatewayPath` 声明，不用命令行传 |
| 部署卡住 20 分钟无输出 | Web 函数缺 `scf_bootstrap`，CLI 在等交互确认 | 已生成 `scf_bootstrap`；再遇到就多喂几个 `y`（`printf 'y\ny\ny\n'\|tcb ...`） |
| 首页 200 但 `/api/me` 返回 HTML | 网关 `enablePathTransmission=true` 把 `/admin` 前缀透传进 Express | 设为 `false`（网关剥前缀），前端就能用 `/app.js`、`/api/*` 绝对路径 |
| 登录一律 500「服务暂时不可用」 | **函数没绑 VPC**，连不上内网 MySQL | cloudbaserc 里加 `vpc: { vpcId, subnetId }`，取自任一能连库的既有函数 |
| `routes add` 报「system internal domain」 | 默认域名不能手工建路由 | 走 `tcb deploy --only gateway` 声明式 |
| 登录 500（VPC/超时/内存都配了还是 500） | **函数没有 DB 环境变量**。`common/db.js` 全部配置来自 `DB_HOST/DB_PORT/DB_USER/DB_PWD/DB_NAME`，新建函数默认一个都没有（`tcb fn env pull admin-web` 拉到空文件）。CLI 3.8.4 **没有 `fn env set`**，只有 `pull` | 用 `node scripts/deploy-admin-web.js`（临时注入 → 部署 → 还原，口令不落盘）。见下节 |
| 课表导入 500，浏览器只显示「服务内部错误」 | 备份段用了 `CREATE TABLE ... LIKE`，而**应用库账号 `classassist_app` 只有 DML 权限**：`ER_TABLEACCESS_DENIED_ERROR 1142`。失败点在事务之前，数据一行没动，但现场看起来像导入功能坏了 | 改成写常备表 `bak_admin_session` / `bak_admin_course`（只需 DML）。门禁 `check-admin-import-ddl.js` 锁死「导入路径零 DDL」 |
| **改密码恒 500**（登录正常、A/B 校验也正常，只有真写库那一步炸） | `admin_user.pass_hash` 首版建 **varchar(128)**（按 bcrypt 60 设计），而 scrypt 格式串 **130 字符**。建号 INSERT 走 tcb 通道（非严格模式）被**静默截断到 128**——截断版仍能登录（verifyPassword 按存储长度推导 dkLen，自洽）；改密 UPDATE 走应用账号（严格模式）130 塞 128 → `ER_DATA_TOO_LONG(1406)` → 500。「能登录、不能改密」瞒到真机改密才爆（2026-10-10） | 列加宽 `ALTER TABLE admin_user MODIFY pass_hash varchar(255)`（已线上执行，备份 `bak_admin_user_pwfix`）；建表真源 `migrate-admin-web.sql` 已改 255。**教训：换哈希算法先核列宽；tcb 通道非严格模式会静默截断，别拿它当「能写进去 = 列够宽」的证据** |
| 云端 500 只回一句人话，定位不了 | `tcb fn log` 报 `topic not exist`（日志通道未开通），堆栈拿不到 | 临时端点 `/api/_diag` 回读内存里最近一次非业务异常的 message/code/sqlState/stack（需超管会话）。**排查完必须删**，见 `index.js` 里该端点的注释 |

⚠️ `fn invoke` 对 **HTTP 型**函数不透传 path（只会 `Cannot POST /`），别用它验证 Web 函数。

### 部署（含 DB 环境变量注入）

CloudBase CLI 没有 `fn env set`，写环境变量的唯一路径是让 `tcb fn deploy` 应用
`cloudbaserc.json` 的 `functions[].envVariables`。但明文口令写进 `cloudbaserc.json`
等于进版本库，所以走脚本：

```bash
node "<tcb>" fn env pull course -e <envId> --output-file .env-course   # 一次性
node scripts/deploy-admin-web.js --dry-run    # 只看键名与长度
node scripts/deploy-admin-web.js             # 注入 → 部署 → 还原
```

脚本行为与安全设计：

- 从 `.env-course` 读 5 个 `DB_*`（**不**取 `WX_APPID`，后台网页没有微信上下文）；
- 注入前先把原样 `cloudbaserc.json` 存到 `.wb_tmp/cloudbaserc.safe.json`，
  下次启动第一件事就是从它恢复 —— 进程被 SIGTERM 硬杀时 `finally` 不会执行，
  没有这层保险口令就留在磁盘上了；
- 注入 → `tcb deploy --only functions` → 无论成败都还原，`finally` + 备份双保险；
- `.env-*` 已在 `.gitignore` 里。

⚠️ 两个实测踩过的坑（改脚本前先读）：

1. **`spawnSync` 在本机会抛 `EBUSY`**（带 stdio pipe 时），且失败时 `status=null`，
   只取 status 会误判成「tcb 部署失败」。脚本已改用异步 `spawn` + 显式打印
   `r.error` / `r.signal`。
2. **`stdio: 'inherit'` 在后台执行时 stdin 是关闭的**，`tcb deploy` 的
   「Overwrite and update? (Y/n)」会永远等下去（实测卡 5 分钟零输出）。
   必须 stdin 走 pipe 并预喂一串 `y`。

### 新建后台账号

```bash
node scripts/admin-create-user.js <username> <member_id> [口令]
# 生成 outputs/admin-create-user.sql，然后：
bash scripts/run_sql_file.sh outputs/admin-create-user.sql
# 用完删掉该 SQL（含口令哈希，已在 .gitignore 里）
```

`member_id` 必须是**真超管且状态正常**。口令不足 10 位会被拒绝。

### 课表导入的自动备份与回滚

导入前自动备份被覆盖的课次与课程行，**只做 DML**（应用库账号无 DDL 权限）：

| 表 | 内容 |
|---|---|
| `bak_admin_session` | 课次备份（batch_no / class_id / group_scope / session_id / course_id / kind / week_rule / weeks / day_of_week / period / duty_count / **note**） |
| `bak_admin_course` | 课程备份（batch_no / course_id / name / teacher / room） |

建表脚本：`scripts/admin-bak-tables.sql`（**已执行过**，含回滚 SQL 模板）。
每次导入生成一个批次号（`YYYYMMDDHHMMSS`），接口返回的 `backupBatch` 就是它。
备份**按批次累积**，不会像原来按时间戳分表那样导一次多一张表。

回滚要点（完整模板见建表脚本注释）：

1. 先查 `SELECT * FROM bak_admin_session WHERE batch_no = '<批次>';` 确认范围；
2. 删掉本次新写入的课次，再从备份 `INSERT ... SELECT` 还原旧课次
   （**`duty_count` 与 `note` 必须一并还原**，note 存的是「地点：xxx」「调课原因」
   这类人工信息，漏了当场看不出来）；
3. 还原课程行 —— ⚠️ `bak_admin_course` 只存 4 个字段，而 `course` 表有 10 个
   （缺 `class_id` / `course_type` / `duty_count` / `created_by` / `created_at`），
   **回滚课程行时这 5 个字段要自己补**，否则还原出来的课程是残缺的。

### 校验

```bash
bash scripts/run_all_gates.sh        # 静态门禁 76 项
bash scripts/run_admin_web_e2e.sh    # 后台 e2e 43 项（需本机 Chromium）
node scripts/check-admin-web.js      # 只跑后台相关 27 项
node scripts/check-admin-import-ddl.js   # 只跑导入路径零 DDL 门禁（35 项）
node scripts/check-admin-gateway-prefix.js  # 只跑网关前缀门禁（31 项）

```

e2e **只 mock 数据库层**，HTTP 路由 / Cookie / 会话回查 / 前端渲染都走真代码。

> ⚠️ **本地 e2e 全绿 ≠ 线上可用**（2026-10-10 实踩）。
> 本地 e2e 跑 `127.0.0.1:3122/admin`，与线上同路径形态，但仍**测不到**
> 「CloudBase 网关只转发 /admin 前缀」这一层 —— 那是**部署之后才存在**的行为。
> 所以每次部署后必须再跑 `verify-admin-web-online.js`。
但它**验不到**（这些是真机补验后才发现问题的）：

- 真 SQL 与生产库结构的一致性、TDSQL 方言；
- **数据库账号权限**（DDL 被拒这类问题 mock 原理上抓不到）；
- 课表导入的真事务、A/B 自动降全体课、`duty_count` 回滚、备份表字段完整性；
- 云函数冷启动与 60s 超时。

> 真机导入验证（2026-10-10）已经暴露出两个 mock 抓不到的真问题：
> ① 应用库账号无 DDL 权限；② 备份表漏了 `note` 与 `course` 的 5 个字段。
> 前者已由门禁 74 锁死，后者靠 `scripts/admin-bak-tables.sql` 的注释提醒。

## 五、数据与安全

| 表 | 用途 |
|---|---|
| `admin_user` | 后台账号（口令哈希 + 登录失败锁定） |
| `admin_session` | 服务端会话（可即时吊销；Cookie 里只有 sid 的 SHA-256） |
| `admin_audit_log` | 操作审计流水 |

- 口令哈希用 **scrypt**（Node 内置）。不用 bcrypt，因为 bcrypt 是原生模块，
  云函数 zip 部署要带二进制、跨平台易炸。
- 连续登录失败 **8 次锁 15 分钟**；会话 **12h 滑动续期**。
- Cookie 是 HttpOnly + SameSite=Lax，HTTPS 下自动加 Secure。
  页面与接口**同源同域**——这是刻意的，跨站会让 HttpOnly Cookie 失效。
- `member` 表**零改动**，后台所有人员 SQL 都显式拼 `NOT_TEST` 过滤测试账号
  （显式写而不是「顺带过滤」，这样漏写能被门禁 grep 出来）。

### 备份表
- `bak_admin_user_20261010`（建账号前的空表备份）
- `bak_session_<时间戳>` / `bak_course_<时间戳>`（每次课表导入自动生成）

回滚一律走**手工 SQL**，不写自动回滚 —— 备份表会越攒越多，自动清理的风险比收益大。

## 六、出事了怎么办

| 症状 | 查什么 |
|---|---|
| 打不开 / 白屏 | `tcb fn log admin-web`，看是否冷启动超时 |
| 登录提示「账号或密码不正确」 | 连续失败 8 次会锁 15 分钟，等或手工 `UPDATE admin_user SET fail_count=0, locked_until=NULL` |
| 登录后立刻掉线 | 绑定的 member 被停用/降权了（真源口径）。查 `SELECT * FROM member WHERE id=<member_id>` |
| 页面数据全是 0 / 表格空 | 多半是 DB 连接问题而非前端问题，先看函数日志里的 `[login-error]` 堆栈 |
| 课表导入后数据不对 | 用返回的 `rollbackHint` 里的 `bak_*` 表名做手工回滚 |

## 七、已知边界（诚实清单）

1. **e2e 覆盖不到真数据库**：真 SQL / TDSQL 方言 / 导入事务 / 冷启动超时，需上线后真机验。
2. **前端没用 amis**（原方案是 amis JSON 低代码）：改用零构建原生页面，
   因为 amis SDK 数 MB 会拖慢云函数冷启动。接口已按 amis RESTful 约定设计，
   后续要换回 amis 只换渲染层。
3. **没有 RBAC**：只有超管一种角色。这是方案刻意决定的，不在 Web 侧重建
   `isCounselor / isCommittee / staffClassIds / resolveClassId`。
4. **无操作日志回溯 UI 的分页筛选**只有模块/班级/时间，够用但简陋。
5. **会话不做跨设备管理界面**：能改密码（会吊销全部会话），但没有「查看所有登录设备」的页面。
