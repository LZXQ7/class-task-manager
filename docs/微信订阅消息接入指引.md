# 微信订阅消息接入指引（值日提醒）

> 目标：第二天有值日的同学，收到**两条**微信服务通知 —— 前一天 **21:00** 预告，值日当天早上 **07:00** 再提醒一次（含具体课次与教室）。
> 整条链路由三部分组成：① 前端弹授权框拿额度 → ② 云函数定时任务组装内容 → ③ 云调用 `subscribeMessage.send` 下发。
> 三部分缺一不可，其中 ②③ 都依赖**同一个模板 ID**。
> ⚠️ 一次性订阅「同意一次 = 1 条」，**一天两条意味着每人每天要消耗 2 条额度** —— 详见 §5。

---

## 1. 现在用的是哪个模板

| 项 | 值 |
|---|---|
| 标题 | 日程提醒 |
| 编号 | 17406 |
| 类目 | 信息查询 |
| 模板 ID | `jU9_n9F15wuTab9dQyehEGrd9fprneyXTiYt3dm0xok` |
| 关键词 | 日程主题 `{{thing1.DATA}}` · 备注 `{{thing2.DATA}}` · 课程名称 `{{thing3.DATA}}` |
| 订阅类型 | 见 §5（一定要看一眼是一次性还是长期） |

三个关键词**都是 `thing` 类纯文本**，各限 20 个字符，没有格式要求——这是它最省心的地方。
之所以不选带「时间 / 开始时间 / 时长」的模板：那些是**时间类**关键词，格式必须是
`2019年10月1日 15:00` 这种，填纯日期会被判参数不合法（`47003`）导致**整条消息发不出去**。

### 本程序往这三格里填什么

| 关键词 | 填充内容（示例） |
|---|---|
| 日程主题 `thing1` | `明天有 2 项值日` |
| 备注 `thing2` | `18点前打扫410、第2节大学英语` |
| 课程名称 `thing3` | `大学英语`（纯保洁日填课次名：周二=`410大扫除`，其余=`打扫410`，这一格不能空） |

> 保洁（`session.kind = 'CLEAN'`）一律写「**18点前+课次名**」：周二为「**18点前410大扫除**」、其余为「**18点前打扫410**」，不写「第 4 节」——
> 它挂在第 4 节上只是为了有个排班位，同学看到「第 4 节打扫 410」会以为是去上课。

## 2. 填两处 ID（只有两处，别漏）

| 位置 | 填什么 | 作用 |
|---|---|---|
| `miniprogram/utils/config.js` → `SUBSCRIBE_TEMPLATE_ID` | 模板 ID | 前端拿它调 `wx.requestSubscribeMessage` 拉起授权框；**留空则所有「开启微信提醒」入口退化成提示文案，不会报错** |
| `cron-weekly` 云函数环境变量 `TEMPLATE_REMIND` | 同一个模板 ID | 服务端拿它调 `subscribeMessage.send` 发消息 |

两处必须是**同一个 ID**，否则用户授权了 A 模板、服务端去发 B 模板，会报 `47003`。

`SUBSCRIBE_TEMPLATE_ID` 已填好；`TEMPLATE_REMIND` 需要在云开发控制台
**云函数 → cron-weekly → 配置 → 环境变量** 里加上：

```
TEMPLATE_REMIND=jU9_n9F15wuTab9dQyehEGrd9fprneyXTiYt3dm0xok
```

## 3. 关键词字段名（模板不同时只改环境变量，不用动代码）

`cron-weekly/index.js` 的 `REMIND_FIELDS` 读取下面这组环境变量，默认值已按当前 3 格模板（thing1/thing2/thing3）对齐：

| 环境变量 | 默认值 | 对应关键词 | 内容形如 |
|---|---|---|---|
| `TEMPLATE_REMIND_F_TITLE` | `thing1` | 日程主题 | `明天有 2 项值日` |
| `TEMPLATE_REMIND_F_DIGEST` | `thing2` | 备注 | `18点前打扫410、第2节大学英语` |
| `TEMPLATE_REMIND_F_COURSE` | `thing3` | 课程名称 | `大学英语` / `打扫410` / `410大扫除` |
| `TEMPLATE_REMIND_F_DATE` | **留空** | 日期（本模板没有） | — |

> ⚠️ **只填模板里真实存在的关键词**。多传一个不存在的字段（比如模板里没有 `date` 却传了 `date2`）
> 会直接 `47003` 发送失败。所以日期字段默认留空，只有当模板确实带「日期」关键词时才设它。

> 字段号是**模板固定的、和你勾选的顺序无关**，必须照着「我的模板」里显示的抄，不能猜。

`thing` 类关键词超 20 字会被截断加 `…`（代码已处理；不截断会导致**整条发送失败**）。

## 4. 版本状态：调试期一定要改成 developer

`cron-weekly` 发送时带了 `miniprogramState`，默认 `formal`（正式版）。
小程序**还没发布**时用 `formal` 会发送失败。调试期请在环境变量里加：

```
TEMPLATE_REMIND_STATE=developer      # 开发版；体验版用 trial；正式发布后删掉或改回 formal
```

消息点击后跳转的页面默认 `pages/duty/index`，要改就设 `TEMPLATE_REMIND_PAGE`（**不要以 `/` 开头**）。

## 5. 一次性订阅说明（这决定提醒能不能持续收到）

- **一次性订阅**：用户同意一次 = 服务端可发 **1 条**。发完额度清零，要再收到就得再同意一次。
  - 用户授权时若勾选「**总是保持以上选择，不再询问**」，之后在小程序里再点「开启微信提醒」或首页「提醒我」，
    会**静默通过、不再弹窗**，每次都累积 1 条额度。
  - 所以小程序里留了两个入口（`我的 → 开启微信提醒`、首页「提醒我」），让同学顺手多点是刻意的设计，
    不是重复功能。
- **长期订阅**：一次授权长期有效，但**只对特定类目开放**（政务民生、医疗、交通、金融、教育等场景），
  需在公众平台申请，审核通过才有。

**结论**：能申请到「长期订阅」提醒最省心；只能拿到「一次性订阅」时，
请提醒同学在小程序里点一次「开启微信提醒」，并在授权框里勾上「总是保持以上选择」。

## 6. 验证方法

1. 在微信开发者工具里点一次「我的 → 开启微信提醒」，确认弹出了订阅授权框（说明模板 ID 填对了）。
2. 让一个**明天确实有值日**的账号点一次授权。
3. 手动触发定时任务，不用等到点（两条链路要分别验）：
   ```bash
   # 前一晚 21:00 那条（预告明天）
   # 走 MCP：manageFunctions(action="invokeFunction", functionName="cron-weekly",
   #                        params={"TriggerName":"remind"})
   # 当天早上 07:00 那条（提醒今天）
   #                          params={"TriggerName":"remindAM"}
   ```
   看返回里的 `data.remind` / `data.remindAM`：
   ```json
   { "when": "tomorrow", "date": "2026-09-25", "receivers": 2, "sent": 1, "refused": 1, "failed": 0 }
   ```
   - `when` = `tomorrow`（21:00 那条）/ `today`（07:00 那条）；`date` = 实际取的那一天
   - `receivers` = 该日有值日且有 openid 的人数
   - `sent` = 成功发出
   - `refused` = 用户没订阅/额度用完（**正常**，不是错误）
   - `failed` = 真问题，去云函数日志看 `[cron-weekly] remind send fail` 后面的错误码

4. 定时器本身：线上应有 **5 个**触发器 —— `weekly` `0 0 20 * * 0 *` / `daily` `0 0 6 * * * *` /
   `hourly` `0 0 * * * * *` / `remind` `0 0 21 * * * *` / **`remindAM` `0 0 7 * * * *`**（CloudBase 7 段：秒 分 时 日 月 周 年）。
   ⚠️ `createFunctionTrigger` 是**整体覆盖**语义，补建时必须一次传齐这 5 个，漏掉的会被删除。

5. 文案自检：21:00 那条的「日程主题」应是「明天有 N 项值日」，「备注」是「第2节410」这类**课次+教室**；
   07:00 那条同构，只是「明天」换成「今天」。教室取自 `course.room`（为空时只写节次）。

## 7. 常见错误码对照

| 错误码 | 含义 | 处理 |
|---|---|---|
| `43101` | 用户拒绝接收 / 订阅额度已用完 | 正常情况，代码计入 `refused`，不报错。让同学重新点一次「开启微信提醒」 |
| `47003` | 模板参数不合法 | 字段名对不上，或往模板里不存在的字段发了数据。核对 §3 的四个环境变量，确认**没有多传**模板里没有的关键词 |
| `47001` | 模板 ID 无效 / 与小程序不匹配 | 检查 `TEMPLATE_REMIND` 是否抄错、是否属于当前小程序 |
| `40003` / `-601033` / 提示无权限调用 | 云函数没有「云调用 openapi」权限 | 用**微信开发者工具**对该函数执行一次「上传并部署」，让它读取 `cloudfunctions/cron-weekly/config.json` 里的 `permissions.openapi: ["subscribeMessage.send"]`；或在云开发控制台为该函数开启云调用权限 |

| 作用 | 位置 |

| 关键词字段名映射 | 同文件 `REMIND_FIELDS` |
| openapi 权限声明 + 触发器（5 个） | `cloudfunctions/cron-weekly/config.json` |

**改完必须做**：`scripts/sync-common.js` 不需要跑（没动 `common/`），但 `cron-weekly` 要用
`manageFunctions(action="updateFunctionCode")` 重新部署，并确认 5 个触发器都在
（`createFunctionTrigger` 是整体覆盖语义）。

> ⚠️ 触发器是**覆盖式**的：`manageFunctions(action="createFunctionTrigger")` 只传新的 `remind` 会把
> 已有的 `weekly` 删掉（2026-09-24 踩过）。补触发器必须一次传齐全集：
> `[{"name":"weekly","type":"timer","config":"0 0 20 * * 0 *"},
>   {"name":"remind","type":"timer","config":"0 0 21 * * * *"}]`
