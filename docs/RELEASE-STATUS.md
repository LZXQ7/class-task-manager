# 微信小程序发布状态跟踪（RELEASE-STATUS）

> **为什么需要本文件**：代码仓库**无法自动感知**你是否已在微信开发者工具「上传」或「提交审核」。
> 每次完成相应操作后，请**主动告知我**，由我补全本表，并同步更新 `HANDOFF.md` 的【主线状态】
> （标记版本的上传/送审日期、跑复核、按需开关审核体验入口 `review-demo`）。

---

## 字段说明

| 字段 | 含义 |
|------|------|
| **版本** | `miniprogram/utils/config.js` 的 `APP_VERSION`（对外版本号） |
| **代码基线** | 对应的 git tag / commit（私有仓库 `class-task-manager-template`） |
| **上传微信平台** | 在微信开发者工具「上传」的日期（生成体验版/开发版） |
| **送审日期** | 提审（提交审核）日期；并标注是否开启 `review-demo` 后门 |
| **审核结果** | 通过 / 驳回 / 待审 / 未送审 |
| **复核** | 上线后是否跑过 `scripts/verify-*` 在线核验 + 全部门禁 |
| **备注** | 审核体验入口开关、驳回原因、回滚等 |

## 每次发版的标准动作清单

1. **代码侧**（已建立的 GitHub 同步约定）
   - bump `APP_VERSION` + 更新 `CHANGELOG.md` / `CHANGELOG-DETAIL.md` / `outputs/vX-更新说明.md`；
   - `git add -A` → `git commit` → `git tag vx.y.z` → `git push origin main --tags`。
2. **提审前必做**（见 `outputs/vX-更新说明.md` 的「提审前必做」）
   - 开启审核体验入口 / 换演示口令 / 置演示标记（`review-demo`）；
   - 跑 `bash scripts/run_all_gates_bounded.sh` 全部门禁全绿。
3. **微信端操作**
   - 微信开发者工具「上传」→ 公众平台「提交审核」；
   - **完成后告诉我**上传日期与送审日期，我补全本表 + 更新 HANDOFF。
4. **审核通过后**
   - 跑 `scripts/disable-review-demo.sql` 关后门；
   - 跑 `scripts/verify-*` 在线核验 + 门禁复核；
   - 告诉我审核结果，我标记为「通过」并写回 HANDOFF。
