# 用户隐私保护指引 · 填写说明

> 项目：班级任务管理（微信小程序）
> 结论先说：**「微信昵称、头像」不要勾选**，因此也不存在要填的"用途"。

---

## 一、为什么不能勾「微信昵称、头像」

| 事实 | 说明 |
|---|---|
| 代码未收集 | `miniprogram/` 与 `cloudfunctions/` 全量检索无 `getUserProfile` / `chooseAvatar` / `input type="nickname"` |
| 头像另有实现 | `miniprogram/utils/util.js:98` 用「姓名首字圆形色牌」按姓名首字母稳定取色，不依赖微信头像 |
| 接口已不可用 | 微信自 2022-10-25 起收回 `wx.getUserProfile`，新小程序只能走「头像昵称填写能力」组件，本项目未接入 |
| 与备案口径冲突 | 备案备注已声明"不含用户自由发布内容功能"，指引再声明收集头像昵称属自相矛盾 |
| 平白增加摩擦 | 勾了之后用户首次进入会多一次隐私授权弹窗，而功能根本用不到它 |

**做法**：在 mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 把「微信昵称、头像」取消勾选。通常保存后重新提交审核即可生效。

---

## 二、如果后台不让取消（兜底用途文案）

仅在你确认确实要接入头像昵称时使用。**注意：填了就必须真的在代码里实现**，否则属"声明收集但未收集"，提审可能被打回。

```
用于在成员列表、值日表与通知中展示你的头像与昵称，便于班级成员相互辨认身份。我们不会将其用于其他用途，也不会对外提供或公开。
```

若要真正实现，需补：`<button open-type="chooseAvatar">` + `<input type="nickname">` 组件，并在 `app.json` 配置 `__usePrivacyCheck__: true`、接入 `wx.requirePrivacyAuthorize`。

## 三、应该勾选的条目（对齐开发文档 16.3）

| # | 后台条目 | 用途（可直接复制） |
|---|---|---|
| 1 | 微信 openid / 用户信息 | 用于识别你的微信身份并完成班级成员绑定，确保本人操作、他人无法冒用。 |
| 2 | 相册（仅写入） | 用于将值日表长图与班级邀请海报保存到你的手机相册。我们不会读取你的相册内容。 |
| 3 | 日历（仅写入） | 用于将值日提醒添加到你的手机日历，仅写入，不会读取已有日程。 |

### ⚠️ 以下两条**不要再勾**（2026-09-24 复核，功能已移除）

| 后台条目 | 为什么取消 |
|---|---|
| 选中的照片或视频信息 | 值日「打卡 + 上传凭证照片」功能已整块删除：前端打卡 FAB 与 `photo-uploader` 组件均已移除，`media` 云函数删掉了 `registerUpload` / `myPhotos` 路由。代码里 `chooseMedia` / `chooseImage` 调用数为 **0**。 |
| 麦克风 | 唯一会录音的是 `components/record-panel`，而该组件**没有任何页面引用**（孤立组件），语音通知上传路径不可达。 |

> 勾了用不到的权限属于「声明收集但未收集」，与本指引第 1 节反对勾选头像昵称是同一类问题，提审有被打回的风险。

---

## 四、两条容易搞错的

1. **学号后 4 位 / 姓名**：由管理员导入名单，属"用户主动填写或由他人代为录入的信息"，微信后台隐私保护指引里**没有对应勾选项**，不需要勾；但必须写进小程序内的《隐私政策》正文。
2. **订阅消息**：不属于个人敏感信息收集，无需在指引中声明，但须在 mp 后台配置订阅消息模板。

---

## 五、勾完之后

- 指引需在提审前提交并审核通过，否则真机上涉及隐私的接口（日历、相册）会被直接拦截。
- 小程序内的《用户协议》与《隐私政策》已落地为二级页：入口 **我的 →「关于」→ 用户协议 / 隐私政策**（页面 `pages/doc/index?type=agreement|privacy`，正文源文件 `miniprogram/data/legal.js`）。**两处文案必须与本指引保持一致**，改任一处都要同步另一处。
- 本指引与站内《隐私政策》**均不得再出现 ICP 备案号**（2026-09-24 起「关于」页已删除备案号展示）。
