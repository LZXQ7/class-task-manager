# 一键生成值日表 · AI 提示词与配置说明

> 对应功能：值日页 → 超级管理员 →「一键生成」→ 弹层里输入一句自然语言 →「AI 生成」→ 预览 →「应用到本周」。

---

## 一、设计原则：模型管「听懂」，程序管「规则 + 配对」

一句话：**AI 只决定「哪些课次不动」和「哪些人本轮跳过」；「谁配到哪节课次」由程序按课次先后顺序取最小序号决定。**

值日表有若干**不能违反**的硬规则，**全部由云函数 `schedule.validatePlan()` 在本地强制**：

| 硬规则 | 由谁保证 |
| --- | --- |
| 分组课只排该组、全体课不限 | 程序 |
| 请假的人当天不排 | 程序 |
| 同一人同一天不排两次 | 程序 |
| **一轮里每人只排一次**（跨天也不重复） | 程序 |
| **谁配到哪节课次**：按「日期 + 节次」先后，依次取最小可用序号 | 程序 |
| 每个课次排几个人（`dutyCount`） | 程序 |
| 「哪些课次不要动」 | **AI** → `unchanged` |
| 「哪些人本轮跳过」 | **AI** → `skipSeqs` |

所以：

- 提示词写得差一点、模型偶尔漏排一节课，**都不会产生错误的值日表** —— 程序会把每个非 `unchanged` 的课次按顺序排满，AI 给的人选写错了也不影响结果。
- 你完全可以放心地按自己的习惯改写提示词，甚至删掉整段规则说明，程序这一层兜得住。
- 真正需要提示词把关的是**语义**：也就是 `unchanged`（哪些课次不动）和 `skipSeqs`（哪些人本轮不排）。

### 为什么配对交给程序（2026-09-24 的一次真实事故）

用户输入「A 组 23 号之前全部排过了，B 组 24 号之前全部排过了」，模型**挑的人是对的**
（A 组用了最小的 10 个可用号、B 组最小的 14 个，24 个名额两两不重复），
但它把 B 组最后两个号（50 示例成员50、52 示例成员52）配给了**最早的** B 组课（周一第 4 节），
却把 46、48 放到了最晚的周四第 5 节 —— 看起来就像「50 号插队排到了周一」。

**人没错，错的是配对顺序。** 现在顺序由程序负责：同一个输入，周一第 4 节必然是最小的可用 B 组号
（30 示例成员30、32 示例成员32）。自检脚本 `scripts/check-seq-order.js` 用这次的真实输入把这行为钉住了。

## 二、默认提示词（当前线上版本）

以下内容与云函数 `schedule/index.js` 里的 `DEFAULT_AI_PROMPT` **逐字一致**
（`scripts/check-seq-order.js` §5 会校验两者同步，改代码忘了改这里会直接报 FAIL）。
线上固定使用这一版 —— 小程序端**不暴露**提示词编辑入口了，改提示词请改源码后重新部署。

```text
你是「班级值日排班助手」。使用者会用一句自然语言描述要求。

# 你的职责（很重要，先看这里）
「谁配到哪节课次」由程序决定 —— 它会按课次的先后顺序，依次取序号最小的同学，
所以「一轮里每人只排一次」「一路往后排、排完再从头」这些规则你不用操心，写错也不会落库。
你要重点判断的只有三件事：
① 哪些课次**保持原样、不要重排** → 写进 unchanged；
② 哪些同学**本轮跳过、不要再排** → 写进 skipSeqs；
③ assignments 里给出你理解的人选（程序可能不采用，但能让使用者核对你的理解）。

# 输入说明
user 消息里带一段 JSON：
- sessions[]：本周要排的课次。sessionId 课次编号；date 日期；dayText 星期；period 第几节；
  course 课程名；room 教室；groupScope 为 "A"/"B" 表示分组课（只对该组开放），null 表示全体课；
  dutyCount 该课次需要几个人；existingDutySeqs 该课次现在已排的人（序号）；
  busySameDaySeqs 当天已被别节课占用的人。（请假信息不再提供，见规则 4）
- roster[]：全班名册。seq 是「序号」（就是使用者口中的「N 号」）；group 是 A/B 组；
  dutyCountThisRound 本轮已经被排过几次（0 = 本轮还没排过，≥1 = 本轮已排过）。

# 必须遵守的硬性规则（优先级最高，与使用者描述冲突时以本节为准）
1. 每个课次的安排人数必须恰好等于 dutyCount，不多不少。
2. groupScope 为 "A" 或 "B" 的课次只能安排该组的同学；groupScope 为 null 的课次任何人都可以。
3. 同一名同学在同一天（同一个 date）最多只出现一次，即使当天有多节课。
4. 【请假不再影响排班】有同学请假也照样给他排 —— 值日先排、之后才知请假，
   请假的同学自行找人换班（小程序内申请换班）。绝对不要因为请假把他排除或跳过，
   也不要为了「避开请假的人」而改别人。
5. busySameDaySeqs 里的同学当天已被占用，只有该课次人数实在凑不齐时才可重复。
6. 公平轮转：优先选 dutyCountThisRound 最小的同学（0 最优先），同一档内按 seq 从小到大取。
7. 【一轮里每人最多排一次】同一个人绝对不能出现在两个课次里，即使这两天不是同一天。
   排班像发号一样一直往后走：本周从「最小的、还没排过的号」开始连续取号，
   下周接着从本周用到的最大号之后继续；直到全班 56 人都排过一次，才重新从 1 号开始。
   dutyCountThisRound ≥ 1 的同学本轮已经排过，不要再给他们排（除非同组可用的人真的不够）。

# 三句最常见的口语该怎么理解（务必照此执行）
A. 「A 组 23 号之前全部排过了」「b 组 20 号之前全部排过了」这类话 = 这些同学本轮已排过，
   本次不要再给他们排。请把它们写进 skipSeqs。注意分别按组判断：A 组的条件是 group="A" 且 seq<=23，
   B 组的条件是 group="B" 且 seq<=20。
B. 「从周四第二节开始排」这类话 = 周四第二节**之前**的所有课次保持原样、不要重排；
   把那些 sessionId 写进 unchanged 数组，只给周四第二节及之后的课次出 memberSeqs。
   「周四第二节」= dayText 为「周四」或日期是周四，且 period >= 2（含第 2 节本身）。
C. 「一直往后排」「这周排到 40 号，下周从 41 号继续」= 使用者在陈述轮转规则，
   程序本身就会照做。你不用为此做任何额外处理（既不用写 unchanged，也不用写 skipSeqs）。

# 输出要求
只输出一个严格 JSON 对象，不要输出任何解释文字，不要用 Markdown 代码块包裹。结构如下：
{
  "assignments": [ { "sessionId": 8, "memberSeqs": [9, 11] } ],
  "unchanged": [1, 2, 3],
  "skipSeqs": [2, 4, 6],
  "notes": "一句话说明本次排班思路，不超过 60 字"
}

字段说明：
- assignments：数组。memberSeqs 用「序号」表示，不要写姓名，不要写 id。
  必须覆盖**所有没有出现在 unchanged 里的** sessionId，一个都不能漏。
  ⚠️ 这只是你的理解：程序会按「课次先后 + 序号从小到大」重新配对，顺序写偏了不影响结果，
  但**不许漏课次、不许编造序号、不许把「本轮跳过」的人写进来**。
- unchanged：使用者要求「从某处开始排」时，该处之前那些**保持不动**的课次 sessionId。没有就返回空数组。
- skipSeqs：本轮不再给这些人排（使用者点名跳过的、或说「N 号之前都排过了」的）。没有就返回空数组。
  注意：skipSeqs 里的人【绝对不要】写进 assignments（系统会自动排除，但请直接别列，以免浪费）。
- notes：给使用者看的一句话说明。
```

### 提示词里几个约定的含义

| 词 | 含义 |
| --- | --- |
| `seq` / 序号 | **学号后两位**（209901030101 → 1）。全项目唯一口径，也天然等于分组（奇=A、偶=B） |
| `dutyCountThisRound` | 本人**本轮**已排次数。0 = 本轮还没排过，最优先 |
| `groupScope` | `"A"` / `"B"` = 分组课，只能排该组；`null` = 全体课 |
| ~~`onLeaveSeqs`~~ | **已移除**（2026-10-07 起请假不参与排班：值日先排、后知请假，请假者自行申请换班） |
| `busySameDaySeqs` | 该课次当天已被其他课次占用的人（含你手动加的值日） |
| `skipSeqs` | 你要求本轮跳过的人。**本周不排，但算作已用掉本轮名额** |

## 三、自然语言可以怎么说

输入框支持 600 字。**所有说法最终只影响两件事：`unchanged`（哪些课次不动）和 `skipSeqs`（哪些人本轮不排）。**

| 说法 | 效果 |
| --- | --- |
| 「A 组 23 号之前全部排过了，B 组 24 号之前全部排过了」 | `skipSeqs` = 「A 组且 ≤23」∪「B 组且 ≤24」 |
| 「1 号和 2 号本轮先跳过」 | `skipSeqs = [1, 2]` |
| 「从周四第二节开始排」 | 周四第 2 节之前的课次写进 `unchanged`（保持原样不动） |
| 「周三这天不要动，其它重新排」 | 周三全部课次写进 `unchanged` |
| 「一直往后排」「这周排到 40 号，下周从 41 号接着排」 | 不用做任何事 —— 程序本来就是这么排的 |
| 不写任何要求直接点生成 | 全班按序号从头轮转 |

输入框里的灰色占位示例（不会真的提交）是：
「A 组 23 号之前全部排过了，B 组 24 号之前全部排过了；从周四第二节开始排，之前的不要动；1 号和 2 号本轮先跳过」

**`unchanged` 的准确含义**：这些课次**原样保留当前的排班**。如果它本来就没有值日，那就保持没人 ——
需要「先排上、再锁定」时，请先在课表页/手动排班页排好，再来生成。

**不支持的写法**（程序没有这些能力，写了也不会生效）：

- 「周三第一节多安排 1 人」→ 每个课次人数固定为 `dutyCount`（默认 2），生成时不能临时改；要改请到课表页改课次配置。
- 「让男生值日」「A 组课排女生」→ 名册里只有 `seq`（序号）和 `group`（A/B 组），没有性别字段。
- 「把示例成员01排到周一第一节」→ 配对顺序由程序决定，AI 不能指定「某人排某节课」；这种需求请用「我的 → 手动排班」。

> 「按序号轮转」按钮是不经过 AI 的纯本地算法（确定性、可复现）；
> 「AI 生成」= **同一套本地取号算法** + 用 DeepSeek 理解你那句话里的 `unchanged` / `skipSeqs`。
> 所以两者排出来的顺序规则完全一致，AI 只是帮你省掉手工指定「跳过谁、从哪节开始」的功夫。

## 四、管理员配置（只需做一次）

由于本环境的 VPC 没有公网出口（路由表为空、无 NAT 网关），
所有业务云函数都**不能直接访问 DeepSeek**，因此专门放了一个不绑 VPC 的出口函数 `ai-proxy`。

**密钥只放在 `ai-proxy` 上，业务函数 `schedule` 完全接触不到密钥。**

在云开发控制台 → 云函数 → `ai-proxy` → 环境变量，配置：

| 变量 | 必填 | 值 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | ✅ | DeepSeek 官方密钥，`sk-` 开头 |
| `AI_PROXY_TOKEN` | ✅ | 共享令牌，需与 `schedule` 上的同名变量一致 |
| `AI_TIMEOUT_MS` | 选填 | 默认 45000，本环境设为 `48000` |
| `DEEPSEEK_BASE_URL` | 选填 | 默认 `https://api.deepseek.com` |

`schedule` 上需要：

| 变量 | 值 |
| --- | --- |
| `AI_PROXY` | `ai-proxy`（出口函数名；置为空字符串则改为直连模式） |
| `AI_PROXY_TOKEN` | 与 `ai-proxy` 相同的令牌 |
| `DEEPSEEK_MODEL` | 选填，默认 `deepseek-chat` |

### 自检

配好后直接调用出口函数验证（不需要登录态）：

```json
{ "action": "ping" }
```

期望返回：

```json
{ "errCode": 0, "data": { "base": "https://api.deepseek.com", "hasKey": true, "egress": "ok", "httpStatus": 200 } }
```

- `egress: "fail"` → 出口函数本身有问题（但它不绑 VPC，一般不会）
- `hasKey: false` → 密钥没配上
- `httpStatus: 401` → 密钥无效或已过期

小程序里也会自动探测：打开「一键生成」弹层时若没接入成功，会显示一行黄色提示。

### 超时预算

微信小程序端 `wx.cloud.callFunction` 的**硬上限是 60 秒**（基础库限制，控制台调不上去），所以链路按倒推配置：

```
DeepSeek 请求最多 48s（ai-proxy 的 AI_TIMEOUT_MS）
   → 函数间调用等 55s（schedule 调 ai-proxy 时显式传的 timeout）
      → 外层函数 60s（schedule 自身超时）
         → 小程序端 60s（不可调）
```

若模型偶发超时，可把 `AI_TIMEOUT_MS` 调小以更快失败重试，而不是调大。

## 五、排障

| 现象 | 原因 / 处理 |
| --- | --- |
| 弹层显示「还没接入 DeepSeek」 | `ai-proxy` 缺 `DEEPSEEK_API_KEY` |
| 提示「无权调用 AI 代理」 | `schedule` 与 `ai-proxy` 的 `AI_PROXY_TOKEN` 不一致 |
| 提示「DeepSeek HTTP 400 … json」 | 修改后的提示词里没有出现 `json` 字样（DeepSeek 的 JSON 模式要求）；线上已在用户消息末尾兜一句，一般不会触发 |
| 提示「AI 返回的不是合法 JSON」 | 模型输出格式跑偏，重试或把描述写得更明确 |
| 生成结果里有「AI 漏排，已按序号轮转补齐」 | 模型漏排了课次，程序已兜底，属正常 |
| 生成了但有黄色告警 | 你的要求与硬规则冲突，告警里写明了哪一条、被剔除的是谁 |
